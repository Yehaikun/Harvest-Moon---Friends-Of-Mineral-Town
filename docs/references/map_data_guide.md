## 2. Spawn / Entry Points

The player's spawn point when entering a map is determined by `Proc016`
(teleport function) parameters, usually followed by `SetEntityPosition`
to place the player.

Spawn points are documented in `docs/generated/warp_index.tsv`. Key columns:

| Column | Meaning |
|--------|---------|
| `map_id` | Destination map ID |
| `proc_x`, `proc_y` | Coordinates passed to Proc016 |
| `entity_x`, `entity_y` | Player position after SetEntityPosition |
| `facing` | Direction the player faces after warp |

### Common Warp Examples

| Source | Warp To | Coordinates | Script |
|--------|---------|-------------|--------|
| Chicken coop door | MAP_BEACH | (24, 280) | script_167 |
| Player house exit | MAP_FARM | (316, 116) | script_6 |
| Shop exit | MAP_NORTH_TOWN | (688, 168) | script_24 |
| Town→Farm path | MAP_FARM | various | multiple |

## 4. Map Coordinate System

Map coordinates use Q16 fixed-point format internally (`s32 x_pos_q16`).

In scripts, coordinates appear as integers in `Proc016(map, x, y)` and
`SetEntityPosition(entity, x, y, facing)`.

### Coordinate Ranges (approximate, per map)

Each map has boundaries. Teleporting outside these bounds causes the
player to appear in a wall or get stuck.

To determine safe coordinates:
1. Open the map in an emulator
2. Walk to the edge and note the RAM address for player position
3. Use those values as bounds for teleport destinations

## 5. Safe Modification Workflow

### Modifying an Entrance/Teleport

1. **Find the script:** Search `warp_index.tsv` for the destination map.
   Example: `grep -n $'^167\t' docs/generated/warp_index.tsv`

2. **Find the source trigger:** Check `script_table_080F1FC0.tsv` to see
   which entity triggers this script.

3. **Edit the script:** Modify `Proc016(new_map, new_x, new_y)` and
   `SetEntityPosition(0, new_x, new_y, new_facing)`.

4. **Verify slot size:** `make pre-build-check`

5. **Build and test:** `make -j2 fomt.gba && mgba-qt fomt.gba`

### Preventing Wall/Black Screen

- Keep the new coordinates within the map's boundaries
- Use existing warp coordinates as reference (same map + similar position)
- `SetEntityPosition` facing parameter: 0=down, 1=up, 2=left, 3=right
- Always provide a `SetEntityPosition` after `Proc016` to ensure the player
  is placed correctly

## 7. Collision / Boundary Candidate Records

### Current Status

The previously documented collision offsets are **not yet verified** as full
64x64 collision grids. The address pattern is real, but it currently looks like
a compact 0x80-byte map-indexed record:

```text
candidate_offset = 0x120BBC + map_id * 0x80
candidate_size   = 0x80
```

Directly unpacking these records with the project popuri/LZSS decoder fails
with `Invalid popuri header`, so they must not be treated as 4112-byte compressed
collision blocks yet.

| Offset | Size | Description |
|--------|------|-------------|
| 0x120BBC | 0x80 candidate | Map 0 (MAP_MOTHERS_HILL) |
| 0x120C3C | 0x80 candidate | Map 1 (MAP_BEACH) |
| 0x120CBC | 0x80 candidate | Map 2 (MAP_FARM) |
| 0x120D3C | 0x80 candidate | Map 3 (MAP_FOREST) |
| 0x120DBC | 0x80 candidate | Map 4 (MAP_CHURCH_REAR) |
| 0x120E3C | 0x80 candidate | Map 5 (MAP_NORTH_TOWN) |

Use the read-only helper before changing anything:

```sh
make collision-candidate-farm
make collision-scan-popuri
```

Generated files go under `docs/generated/collision/`.

### Working Hypotheses

These 0x80-byte records may be one of:

- collision or boundary metadata,
- map dimension/camera metadata,
- a pointer/index table into visual or collision resources,
- compact per-map trigger/object flags.

They are useful because the map ID stride is clear. They are not enough to
support safe map expansion by themselves.

### Still Needed

To safely enlarge maps, we still need to locate and verify:

- the real walk/block grid used by movement,
- the visual tilemap,
- map width/height and camera boundary values,
- door/object trigger records.

Any old notes that mention a 4112-byte farm collision grid should be treated as
unconfirmed until matched against game behavior and the loading code.
